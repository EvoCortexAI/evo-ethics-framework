# Security Policy

EvoEthics is security-sensitive because a policy error can either block legitimate work or permit an operation that should have been denied.

Please do not publish exploitable bypasses, signing-key issues, approval-replay paths, or sensitive audit-data exposures in a public issue. Use GitHub private vulnerability reporting when it is enabled for the repository, or contact the repository owner through an established private channel.

Security reports should include:

- affected version and policy digest
- action and decision path
- whether the issue permits bypass, downgrade, replay, tampering, data exposure, or denial of service
- a minimal reproduction without real user data or secrets
- suggested mitigation when known

No production support window is claimed while the repository status is `In development`.
